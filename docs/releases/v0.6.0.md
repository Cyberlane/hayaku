# Hayaku v0.6.0

Local release candidate; native acceptance passed. Artifact checks and publication
are pending.

Go and TypeScript/Vitest now share native workspace execution, authenticated
group receipts, complete inventories, full original fallback and aggregate
ownership. `native-init` writes a new reproducible configuration using installed
inputs and preserves existing files.

The restricted Go profile adds compiler-resolved local helpers, external test
packages and literal read-only string embeds. Groups are explicit test packages.
The locked TypeScript/Vitest profile discovers every matching test file and
binds each file to its reachable pure source graph and exact native case outcomes.
Groups are test files. Historical test coverage does not authorize reuse.

Unsupported code, setup, tools or invocation settings run the complete configured
original scope on every invocation. Failed/skipped/incomplete native outcomes
cannot create reusable passing receipts. Forced audits revoke this authority's
history before running original scopes; foreign authority data is preserved.
Later source drift and cleanup failures invalidate the aggregate run and revoke
its attempted receipts.

Go uses the qualified macOS system sandbox or Linux Landlock/seccomp context.
The installed acceptance matrix passed on macOS ARM64 and Linux ARM64. The two
AMD64 targets are build-only archive targets; their v0.6.0 artifact checks are
pending. This release packages four macOS/Linux archives and excludes Windows.
Typed Go qualification requires both
Hayaku and the selected compiler to use Go 1.27.1.
The initial TypeScript original/runtime profile is Linux ARM64, usable from
macOS ARM64 or Linux ARM64 controllers, with fixed Node 22.18.0, TypeScript 6.0.2,
Vitest 4.1.11, Vite 8.2.2 and Rolldown 1.2.12 inputs. It requires separately
installed Docker, immutable image, ELF loader/library roles and publisher-pinned
SDK bytes. Hayaku performs no automatic installation or network fetch.

The trusted managed compiler profile permits the executable memory required by
Node/V8 and the fixed framework. It relies on that compiler/framework/addon
trusted computing base; it does not claim W^X or arbitrary native program
equivalence. Public source summaries, input bundles and runtime captures remain
descriptive and cannot mint omission authority.

See [setup and supported profiles](../go-typescript-native.md),
[implementation status](../implementation-status.md) and
[release gates](../go-typescript-release-plan.md) for evidence and limits.
Warm verification still has capture/build/collection costs; tiny suites can be
faster in full. Performance claims require measured end-to-end results.

Windows qualification and further language expansion are deferred. Future
releases add one language at a time. Cross-compiled archives do not qualify a
platform or runner, and local tests do not establish hosted CI or consumer
acceptance.
