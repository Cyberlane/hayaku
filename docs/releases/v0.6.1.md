# Hayaku v0.6.1

Go and TypeScript/Vitest native workspaces are available for the documented
restricted profiles. This patch formats six Go fixture files after the hosted
v0.6.0 release gate rejected their formatting. The failed signed v0.6.0 tag is
preserved; it did not publish a release. The normalized fixture programs are
unchanged. Runtime qualification and safety behavior are unchanged from the
locally accepted v0.6.0 implementation. The v0.6.0 hosted Apple lane also rejected
its installed toolchain because the captured producer exceeded its byte limit;
Apple acceptance is unqualified for this release and remains deferred.

Publication runs full repository tests, race checks and vet on Linux and macOS,
the four existing Vitest compatibility pairs on both hosts, and the WASI pilot.
Installed Apple and other-language acceptance lanes remain in ordinary CI and
do not gate this Go/TypeScript release. This preserves their visible failures
without claiming those runners are qualified for v0.6.1.

`hayaku native` shares authenticated group reuse, complete inventories, audits
and full original fallback. Go groups are explicit test packages with reviewed
pure local helpers, external test packages and literal read-only string embeds.
TypeScript/Vitest groups are test files in a locked pure source graph. Historical
test coverage does not authorize reuse. Unsupported syntax, effects, hooks,
tools or invocation settings execute the complete configured original scope.

The qualified Go profile requires Hayaku and its compiler to use Go 1.27.1 on
macOS ARM64 or Linux ARM64. TypeScript/Vitest uses a fixed Linux ARM64 runtime,
controlled from macOS ARM64 or Linux ARM64: Node 22.18.0, TypeScript 6.0.2,
Vitest 4.1.11, Vite 8.2.2 and Rolldown 1.2.12. Separately installed Docker,
an immutable image and pinned SDK bytes are required. Hayaku installs nothing
and performs no automatic network fetch.

Four macOS/Linux archives are provided. AMD64 archives do not qualify affected
native execution. Windows and further language qualification are deferred;
future releases add one language at a time. Local checks and the existing hosted
publication workflow do not establish external consumer acceptance or additional
native profiles. Tiny fixtures run faster in full; representative performance
claims require measured end-to-end results.
